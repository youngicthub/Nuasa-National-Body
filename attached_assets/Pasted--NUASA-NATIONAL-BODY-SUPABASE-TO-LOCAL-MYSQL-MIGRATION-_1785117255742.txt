# NUASA NATIONAL BODY — SUPABASE TO LOCAL MYSQL MIGRATION

You are working on an existing NUASA National Body website originally built with Lovable AI.

The project currently uses Supabase, but the Supabase project is paused. Your task is to migrate the existing project to a local MySQL database while preserving all existing functionality, UI, routes, API endpoints, authentication, admin features, and data relationships.

Do not rebuild or redesign the project. First inspect the existing codebase, then execute the migration.

Scan the entire repository and identify:

Use the actual existing project structure. Do not invent tables, columns, API endpoints, or functionality.

Preserve:

* Existing table names where possible

* Indexes
* Unique constraints
* Important defaults


It must work with MySQL Workbench, phpMyAdmin, XAMPP MySQL, and MAMP MySQL.

* Email verification
* Resend verification email
* Password reset if currently available

* MySQL
* bcrypt
* JWT or secure HTTP-only sessions
* Nodemailer

1. Validate the input.
2. Check for existing email.
3. Hash the password with bcrypt.
4. Create the user in MySQL.
5. Assign the default user role.
6. Set email verification to false.
7. Generate a secure verification token.
8. Store only the hashed token.
9. Send a verification email using Nodemailer.

User signin must:

1. Validate credentials.
2. Verify the password.
3. Check account status.
4. Check email verification status where required.
5. Create a secure session or JWT.
6. Return only safe user information.

# 7. EMAIL VERIFICATION WITH NODEMAILER

Remove Supabase email verification and use Nodemailer.

Install if necessary:

```bash
npm install nodemailer
```

Create a reusable email service.

When a user or admin registers:

1. Generate a secure random token using Node.js crypto.
2. Store only the hashed token.
3. Set an expiration time.
4. Send the verification email using Nodemailer.
5. Verify the token through the backend.
6. Mark the account as verified.
7. Invalidate the token after use.

Use a suitable existing database structure or add the necessary email verification fields/table.

Support:

* Email verification
* Resend verification email
* Password reset emails if currently available
* Admin invitation emails if an invitation system is used

Never hardcode SMTP credentials.

Add to `.env.example`:

```env

SMTP_PASSWORD=your_email_password_or_app_password
```
