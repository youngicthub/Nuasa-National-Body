# NUASA PROJECT — SUPABASE TO LOCAL MYSQL MIGRATION

You are working on an existing NUASA National Body website built with Lovable AI. The project currently uses Supabase, but the Supabase project is paused. The goal is to make the project run completely locally using MySQL while preserving all existing functionality.

## IMPORTANT

Do not rebuild or redesign the project.

First inspect the entire codebase, then execute the migration. Do not spend unnecessary time explaining the plan. Focus on completing the work.

---

## 1. AUDIT THE EXISTING PROJECT

Scan the entire repository and identify:

* All Supabase database queries and client usage
* Supabase Auth
* Supabase Storage
* Supabase RPC/functions
* Realtime subscriptions
* Database migrations and schema files
* All tables, columns, relationships, keys, indexes, triggers, functions, enums, and RLS policies
* All frontend pages and routes
* All backend/API endpoints
* User and admin functionality

Use the actual existing project structure. Do not invent tables or functionality.

---

## 2. MIGRATE THE DATABASE TO MYSQL

Replace Supabase/PostgreSQL database functionality with MySQL 8+.

Use the existing schema and preserve:

* Table names
* Column names
* Relationships
* Primary keys
* Foreign keys
* Indexes
* Unique constraints
* Important defaults
* Existing data where accessible

Convert PostgreSQL types correctly to MySQL equivalents.

Create:

```text
database.sql
```

This file must recreate the complete database and be importable with:

```bash
mysql -u root -p < database.sql
```

---

## 3. REPLACE SUPABASE DATABASE ACCESS

Use the existing backend architecture.

If Node.js/Express is used, use `mysql2` with a connection pool and parameterized queries.

Create or update the database connection using environment variables:

```env
DB_HOST=localhost
DB_PORT=3306
DB_NAME=nuasa_database
DB_USER=root
DB_PASSWORD=
```

Never hardcode credentials.

Never use unsafe SQL string concatenation.

---

Find and document all existing API endpoints before changing them.

Preserve their:

* HTTP methods
* Paths
* Request formats
* Response formats
* Authentication
* Authorization
* Existing frontend behavior

If the frontend currently calls Supabase directly, create equivalent local backend API endpoints and update the frontend to use them.

Do not unnecessarily change the API contract.

# 6. ADMIN AUTHENTICATION

Implement or preserve separate administrator authentication:

```text
Admin signup or secure admin invitation
Admin signin
Admin logout
Admin session/current admin
Role-based access control
Protected admin routes and APIs
```

Do not allow unrestricted public admin registration.

Use either:

1. Existing authorized admin invitation flow, or
2. A protected `ADMIN_SIGNUP_SECRET` environment variable.

Example:

```env
ADMIN_SIGNUP_SECRET=replace_with_secure_secret
```

A normal user must never be able to access admin APIs by changing frontend requests.

Authorization must always be enforced on the backend.

Preserve existing admin roles such as `admin`, `super_admin`, `editor`, or other roles actually found in the project.

---

# 7. EMAIL VERIFICATION WITH NODEMAILER

Remove Supabase email verification.

Use Nodemailer.

Install if necessary:

```bash
npm install nodemailer
```

When a user or admin registers:

1. Generate a secure random token using Node.js crypto.
2. Store only the hashed token.
3. Set an expiration time.
4. Send the verification email using Nodemailer.
5. Verify the token through the backend.
6. Mark the account as verified.
7. Invalidate the token after use.

Use an existing suitable database structure or add the necessary fields/table.

Create a reusable email service.

Add to `.env.example`:

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=your_email@example.com
SMTP_PASSWORD=your_email_password_or_app_password

MAIL_FROM_NAME=NUASA National Body
MAIL_FROM_EMAIL=your_email@example.com
```

Never hardcode SMTP credentials.

Support:

```text
Email verification
Resend verification email
Password reset emails if the existing application supports password reset
Admin invitation emails if an invitation system is used
```
